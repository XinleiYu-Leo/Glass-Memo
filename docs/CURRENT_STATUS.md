# 当前进度与证据边界

基准日期：2026-11-06。本页区分已经完成的工作、已有结果与下一步假设。

## 已完成

1. **采集**：Meta SDK 1.0.1；普通录像保留原行为；多传感器默认关闭，当前请求 high@7，IMU 可选 60/30 Hz，流内音频可独立开关。视频、音频、Motion 使用同一 DeviceSession，Motion 在摄像头 streaming 后启动，传感器失败会记录原因，视频继续保存。
2. **诊断**：每帧/音频块/IMU 保留 SDK 时间和同一个手机单调时钟的到达时间；写入七个文件。0 帧音频回调记为 ignored_empty；多传感器视频使用源 PTS 相对首个成功写入帧的时间轴。
3. **找物 demo**：有本地事件记忆、证据展示和可选的自动分析原型。共享版换成虚构素材。训练出的轻量模型尚未接入此流程。
4. **训练与基线**：完成弱标签规则、数据来源隔离、学习曲线、时序消融、部分微调和音频实验；保存了可用分类头与部分 checkpoint。另有 100DOH 手物检测试跑，只能证明检测到了交互线索。

## 多传感器最新结果

以下三段各录一次；聚合原件见 [multisensor_comparison.json](../experiments/multisensor/multisensor_comparison.json)。不附原视频、音频或原始传感器数据。

| 指标 | A：60 Hz / 音频开 | B：30 Hz / 音频开 | C：30 Hz / 音频关 |
|---|---:|---:|---:|
| 视频时长 | 112.935 s | 97.330 s | 94.813 s |
| 收到/写入/解码帧数 | 780 | 667 | 623 |
| IMU 样本 | 6314 | 2859 | 2897 |
| 最长 IMU 源时间间隔 | 10.425 s | 3.630 s | 0.194 s |
| 最长手机接收停顿 | 15.861 s | 13.612 s | 8.118 s |
| App 侧录队列溢出 | 0 | 0 | 0 |
| 原生 720×1280 帧 | 1/780 | 9/667 | 313/623 |

三段视频的解码时间轴均匹配相对 SDK PTS。A/B 音频载荷与 CSV 累计样本一致；C 确实关闭音频，WAV 只有空文件头。

**可以说**：这次关音频后，保存下来的 IMU 源时间连续性改善；仍有 8 秒级交付停顿，随后大量样本补回。App 写盘排队是毫秒级，无队列溢出。

**不能说**：已经稳定修复、证明音频是唯一原因、无丢帧、实时同步完成。配置间动作、无线条件和原生视频尺寸构成都不同；每档只有一次。IMU 源缺口与主机交付延迟是不同问题。约 2.43–2.48 s 的 IMU/视频内容相关偏移只是逐段探索估计，不能硬编码为时钟校准值。

C 仍有三个约 2 秒的视频源间隔，与分辨率切换共同出现。近似对齐后的 IMU 短缺口也在这些区间，尚不足以推断因果。7 fps 的单帧间隔约 143 ms，不能声称毫秒级同步精度。

## 模型阶段结果

当前主线：Ego4D FHO 人工动作标注构造弱标签，判断过去 1.5 秒的 10 帧是否有拿起/放下转移事件；MobileNetV3-Small 特征冻结，再训练时序汇总分类头。训练规模 200/500/1000/1652，扩充检查集上的 10 帧 MLP AP 约 0.700/0.729/0.751/0.742。

指标和比较的准确口径见 [FHO 说明](../training/fho/README.md) 与 [AP/置信区间核对](../training/fho/MODELS_AP_CI_RECONCILIATION.md)。不能将不同种子平均、保存模型和配对比较数字混为一个模型的成绩。第一次默认 CFR 补帧导致的运行已标记作废，保留原因以防误用。

时间信息对当前任务有价值；继续加样本、运动流、部分微调和声音融合尚未显示稳定增益。标签可见性、域差异可能是瓶颈，但仍是假设，不能排除模型/采样设计因素。检查集并非完整逐帧人工金标准。AP 约 0.75 不是“75% 的找物准确率”。
